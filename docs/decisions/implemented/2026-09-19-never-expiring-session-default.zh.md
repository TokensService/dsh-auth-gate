# 默认会话永不过期，有限会话确定性到期（2026-09-19）

## 决定了什么

`sessionTtl` 默认改为 `0`，表示应用层会话永不过期。会话行以 `expiresAt: 0`
作为哨兵，校验与过期清理都不会把它视为过期。登录 Cookie 仍需要浏览器可存储的
有限寿命，因此应用层永不过期的会话使用 `Max-Age=2147483647`；手工登出继续使用
`Max-Age=0`，并吊销服务端会话行。

有限超时继续受支持。设置 API 接受 `0` 或 [60, 31536000] 范围内的整数，用户
管理页在整小时输入之外提供明确的「永不过期」选项。`/auth/status` 以 `expiresAt`
返回有限会话的绝对过期时间（epoch 毫秒）；永不过期或未登录时为 `null`。client
同时返回 `serverTime`，client 无需依赖浏览器墙上时钟即可算出相对剩余时长。
client 启动后立即探测状态，有限会话按该时长在本地定时；并发时只允许最新发起的
探测提交响应，较旧探测无论先后完成都被丢弃。周期、焦点和可见性探测继续用于发现
吊销和跨标签页变化。

升级时不会改写已有 `settings.yaml` 值，它们仍是显式策略。TTL 修改仍只影响之后
新签发的会话。

## 背景

此前默认七天过期，不符合「除非手工退出，否则保持登录」的部署预期。运行期超时
设置实际会作用于新会话，但存量会话保留签发时确定的有效期，因此修改后容易看起来
像没有生效。

有限会话还有另一个可见问题：dsh web 是长寿命 SPA。服务端会话到期后，已经渲染的
页面可能继续停留，直到之后的请求或状态探测发现失效。只靠轮询也会让跳转时间依赖
定时器调度，以及到期后的网络响应是否成功。

## 考虑过的替代方案

- **保留七天默认值**：否决。它与目标默认策略相反，也迫使每个部署都创建覆盖。
- **只保留既有 30 秒状态轮询**：否决。标签页节流或到期时探测失败时，过期 SPA
  仍可能继续显示。
- **永不过期会话使用 `Max-Age=0`**：否决。浏览器把它解释为立即删除 Cookie；
  应用层无限期和 Cookie 删除必须使用不同表示。
- **把设置修改作用到已签发会话**：否决。这样会静默延长或缩短签发时已经确定的
  凭证寿命；操作员仍可显式吊销或退出这些会话。

## 为什么这样选

零值哨兵无需存储迁移，因为持久化 schema 已接受非负时间戳。较大的可移植 Cookie
寿命让浏览器存储在实践中长期有效，服务端仍是权威；浏览器仍可能按自身策略清理或
限制持久 Cookie。透出绝对过期时间与服务端时间后，浏览器无需依赖自身墙上时钟或
截止点之后的网络响应，也能在目标时间离开旧 SPA。响应排序避免任何在途旧探测触发
跳转或覆盖较新的会话状态。周期状态探测继续负责发现吊销，而暂时性探测失败既不会误登出，
也不会取消已经安排的到期跳转。
